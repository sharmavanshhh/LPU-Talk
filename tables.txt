=== TABLE 6 ===
Variable | Where to Get It | Notes
NEXT_PUBLIC_SUPABASE_URL | Supabase Dashboard → Project Settings → API → Project URL | Safe to expose — starts with https://
NEXT_PUBLIC_SUPABASE_ANON_KEY | Supabase Dashboard → Project Settings → API → anon public key | Safe to expose — used in browser. RLS policies protect data.
SUPABASE_SERVICE_ROLE_KEY | Supabase Dashboard → Project Settings → API → service_role secret key | NEVER expose this! Server-side only. Bypasses RLS.
GEMINI_API_KEY | Google AI Studio → aistudio.google.com → Get API Key → Create API Key | Server-side only. Free tier available. Never use NEXT_PUBLIC_ prefix.
NEXT_PUBLIC_APP_URL | Set manually — localhost:3000 for dev, your Vercel domain in production | Used for OAuth redirect URLs

=== TABLE 7 ===
Area | Check | How
API Auth | All /api/chat routes require valid Supabase JWT | withAuth() middleware on every protected route
API Auth | Service role key never exposed to browser | Only used in server-side API routes, not in NEXT_PUBLIC_ vars
Database | RLS enabled on all tables | auth.uid() = user_id on all policies
Database | Users cannot access others' chats | RLS policy: user_id must match auth.uid()
AI Restriction | Gemini system prompt enforces LPU-only | Sent on every API call — cannot be bypassed by user
AI Restriction | Optional keyword pre-filter saves API budget | isLikelyLPUQuery() check before calling Gemini
Input | Max message length enforced | Validate: message.length <= 1000 in API route
Input | Rate limiting on /api/chat | Add Vercel Edge rate limiting or check Supabase quotas
Secrets | .env.local in .gitignore | Never committed to version control
Auth | OAuth redirects validated by Supabase | Supabase only accepts registered callback URLs
